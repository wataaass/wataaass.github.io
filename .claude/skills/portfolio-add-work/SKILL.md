# portfolio-add-work: 作品の追加

手順は最後まで Claude が進める。ただし、経歴にあたる事実（制作期間、役割分担など）は推測で書かない。

## 1. 材料を集める

必要な項目は次のとおり。

- 作品名、ファイル名（英小文字とハイフン。例: `todo-app.html`）
- 制作期間（開始日、終了日または「制作中」）、制作時の学年
- 使った AI ツールとモデル、使った技術
- 自分の役割と AI の役割
- 作った理由、工夫したところ、学んだこと
- 公開 URL やリポジトリ（あれば）

指示文、作品のリポジトリ（README、DECISIONS.md、git log）、study-log から埋める。それでも埋まらない事実だけを、質問機能で1回にまとめて聞く。

## 2. 作品ページを作る

`works/portfolio-site.html` を雛形にして `works/<ファイル名>.html` を作る。

- `<title>`、`description`、`og:*` を作品に合わせる
- 作品名の下の `work-date` と、ページ最後の奥付（`work-okuzuke`）の両方に制作期間を書く
- 本文は「作った理由」「工夫したところ」「学んだこと」の3節。本人の答えをもとに書き、natural-japanese で推敲する

## 3. ほかのページを更新する

- `works/index.html`: `<ol class="catalog">` に行を足す。新しい作品ほど上（制作開始が新しい順）
- `timeline.html`: 節目になる出来事なら、`<ol class="timeline">` に足す。古い順なので日付の位置に入れる
- 全ページのフッターの「最終更新」と、README の「最終更新日」を今日の日付にする（portfolio-edit-common の手順で全ページそろえる）
- README の「ページ構成」は `works/*.html` でまとめて書いてあるので、作品ごとには足さない。作品追加の中で新しく決めたことがあれば「設計上の判断」に「何を：なぜ」の形で足す

## 4. 確認

`npm run check` を実行し、`npm run serve` の状態で表示を確かめる（verify の手順）。公開は portfolio-publish で行う。
